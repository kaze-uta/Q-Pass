# Q-Pass — QRコードによるオフラインファイル転送

ネットワークを使わずに、**画面に表示したQRコードを別端末のWebカメラで読み取る**ことでファイルを転送するツールです。送信側がファイルを分割して連続QRコードとして表示し、受信側がカメラで順に読み取って元のファイルを復元します。

物理的にネットワークが分離された環境（エアギャップ）など、通信経路を使わずに少量のデータを渡したい場面を想定しています。

---

## 仕組み

```
[送信側 PC]                          [受信側 PC]
 ファイル                             Webカメラ
   │ 200バイトごとに分割                │ pyzbar でデコード
   │ 各チャンクを Base64 化             │ Base64 をデコード
   ▼                                   ▼
 QRコードを2秒ごとに順次表示 ──カメラ──▶ 順番に読み取り
   1枚目  : 拡張子                     1枚目  : 拡張子を取得
   2枚目〜: データ本体                  2枚目〜: get.<拡張子> に追記
   最終枚 : "last" マーカー             "last" を検出したら終了
```

- **1枚目のQRコード**: 送信ファイルの拡張子（例: `txt`, `png`）
- **2枚目以降**: ファイルデータを `CAPACITY`（既定 200）バイトずつに分割したチャンク
- **最後のQRコード**: 転送終了を示す `last` マーカー

すべてのQRコードの中身は Base64 でエンコードされています。受信側は読み取ったデータをデコードし、`get.<拡張子>` というファイルに追記しながら復元します。

送信側では「QRコードの生成」と「画面表示」を別スレッドで並列に実行するため、全枚数の生成完了を待たずに表示が始まります。表示済みのQR画像（`qrcode<N>.png`）は自動的に削除されます。

## 必要環境

- Python 3.x
- 送信側端末（画面表示用）と受信側端末（Webカメラ付き）

### 依存ライブラリ

| 用途 | パッケージ | 使用箇所 |
| --- | --- | --- |
| QRコード生成 | `qrcode` | 送信側 |
| 画像処理 | `Pillow` | 送信側 |
| 画面表示・カメラ入力 | `opencv-python` | 送信側・受信側 |
| QRコードデコード | `pyzbar` | 受信側 |
| 配列処理 | `numpy` | 受信側 |

インストール:

```bash
pip install qrcode pillow opencv-python pyzbar numpy
```

> **注意**: `pyzbar` は内部で ZBar ライブラリを使用します。
> - Windows: `pip install pyzbar` だけで ZBar の DLL も同梱されます。
> - macOS: `brew install zbar`
> - Linux (Debian/Ubuntu): `sudo apt install libzbar0`

## 使い方

2台の端末を向かい合わせ、送信側の画面が受信側のカメラに映るように配置します。

### 1. 受信側を起動（先に待機させる）

```bash
cd receive
python receive.py
```

Webカメラの映像ウィンドウが開き、QRコードの読み取り待機状態になります。検出したQRコードは青い枠で表示されます。

> カメラは `cv.VideoCapture(1)`（外付けカメラ想定）で開いています。内蔵カメラを使う場合は `receive/receive.py` の `1` を `0` に変更してください。

### 2. 送信側でファイルを表示

```bash
cd send
python send.py <転送したいファイルパス>
```

例:

```bash
python send.py test.txt
```

起動から約3秒後にQRコードの表示が始まり、2秒ごとに次のQRコードへ切り替わります。受信側のカメラがそれを順次読み取り、`last` マーカーを検出すると受信側のカレントディレクトリに `get.<拡張子>`（例: `get.txt`）が生成されます。

### 終了

- 受信側は `last` マーカーを読み取ると自動的に終了します。途中で止める場合はウィンドウ選択中に `q` キーを押します。
- 送信側はすべてのQRコードを表示し終えると自動的に終了します。

## 設定

| 項目 | 場所 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `CAPACITY` | `send/send.py` | `200` | QR1枚に詰めるバイト数。Base64 化で約4/3倍に膨らむ。大きいほど枚数は減るがQRが複雑になり読み取りにくくなる |
| `cv2.waitKey(2000)` | `send/send.py` `show_qr()` | `2000` (ms) | 1枚あたりの表示時間。受信側の読み取りが追いつかない場合は長くする |
| `time.sleep(3)` | `send/send.py` `show_qr()` | `3` (秒) | 表示開始までの待ち時間。QR生成が表示に追いつくためのバッファ |
| `cv.VideoCapture(1)` | `receive/receive.py` `read_qr()` | `1` | 使用するカメラの番号 |

## 制限事項・注意点

- 転送は**一方向**（送信側 → 受信側）です。
- 転送するファイル名には拡張子が必要です（拡張子のないファイルは扱えません）。
- 受信側は `get.<拡張子>` に**追記モード**で書き込みます。同名ファイルが残っていると前回分の後ろに連結されるため、受信前に削除してください。
- 送信側は作業ディレクトリに `qrcode<N>.png` を一時生成します。前回の実行が途中で止まった場合などは残ったファイルを削除してから実行してください。
- 重複読み取りの防止は「直前に読んだQRと同じかどうか」で判定しているため、**まったく同じ内容のチャンクが連続する**（ゼロ埋め領域など）と2枚目が読み飛ばされ、ファイルが壊れる場合があります。
- シーケンス番号やチェックサムによる整合性検証、取りこぼし時の再送はありません。同期はQRの切り替え速度（タイマー）に依存する簡易方式のため、確実性が必要な用途には適しません。
- カメラの解像度・照明・画面との距離によって読み取り精度が左右されます。読み取りに失敗する場合は `CAPACITY` を下げる、または表示時間を延ばしてください。
- 大きなファイルはQRコードの枚数が増え、転送に時間がかかります。少量データの受け渡しに向いています。
